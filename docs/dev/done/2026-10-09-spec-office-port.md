# Выборочный перенос обработки Office

Дата: 2026-10-09. Задача: SEL-2026-10-09-pii-office-port.

## Проблема и намерение

DOCX/XLSX сейчас пропускают часть текстовых каналов и метаданных. Применяем решение от 01.10.2026 о разборе служебных частей, сохраняя INV-MASK-01 (реестр соответствует заменам), INV-MASK-12 (формат) и INV-MASK-13 (неподдерживаемый текст вызывает отказ).

Обрабатываем текст обычных и вложенных абзацев Word, включая продолжение внешнего абзаца после textbox. Удаленный текст w:delText маскируется, оставаясь удаленным. Текст инструкций полей w:instrText и атрибут w:fldSimple/@w:instr маскируется; отдельные поля не склеиваются друг с другом или видимым текстом. Внешние Target отношений маскируются как отдельные значения; внутренние отношения сохраняются.

Авторство правок и комментариев, инициалы и идентичности people/persons очищаются без восстановления. Свойства core/app/custom, способные содержать персональный текст (автор, редактор, заголовок, тема, описание, ключевые слова, категория, компания, менеджер, пользовательские строковые свойства), очищаются без восстановления; технические свойства сохраняются. Очистка метаданных не создает фиктивные записи реестра.

В XLSX печатные колонтитулы и threaded comments проходят маскирование; управляющие коды колонтитулов сохраняются. Идентификаторы связей комментариев сохраняются, сведения об авторах очищаются. Изменения корректно экранируются в XML, самозакрывающиеся теги не поглощают соседний текст. Текст поддерживаемого типа вне обрабатываемого контейнера приводит к явному отказу вместо тихого пропуска.

## Критерии приемки (OFFICE-PORT)

1. Сценарии Word: текст после/внутри textbox; delText и статус удаления; instrText разных полей; fldSimple; внешние ссылки; авторы/инициалы и people.xml; свойства документа.
2. Сценарии Excel: header/footer с сохранением управляющих кодов; threaded comments; persons; общая очистка свойств.
3. XML: self-closing, экранирование текста/атрибутов и отказ на текст вне контейнера. ZIP валиден, значимые неизменяемые части и внутренние отношения сохраняются.
4. Для исправлений сохранен воспроизводимый RED; полный набор и tests/test_latin_names.py tests/test_tech_terms.py проходят после изменений. Отдельная контрольная проверка старой реализации подтверждает чувствительность регрессий.
5. Публичный Python API pii_mask и CLI неизменны, NER не переносится из форка. MIT-атрибуция сохранена.
6. Происхождение фикстур и ограничения явно указаны. Синтетические ZIP/XML не считаются доказательством открытия в Word/Excel или проверкой реального клиентского файла.

## Принятые границы

Переносим поведение, не архитектуру форка. Не входят .doc, PDF, CLI/API/NER-рефакторинг, деплой, кэш формул XLSX, изображения, вложенные объекты и произвольные XML-каналы. Остатки Д-4 сохраняются в доменной спеке. Новых зависимостей нет.
